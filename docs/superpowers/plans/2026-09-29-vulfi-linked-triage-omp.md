# VulFi Linked Triage and OMP Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a reviewer deliberately link verified IDA and fallback findings, maintain one guarded assessment mirrored to IDB and SQLite across failures, and display preparation, independent triage, and sync health in an optional OMP TUI without modifying native todos.

**Architecture:** Start only after [IDA core](2026-09-29-vulfi-ida-core.md), [preparation/review](2026-09-29-vulfi-re-preparation.md), and [external providers](2026-09-29-vulfi-mcp-fallback.md) are working. `catalog.py` stores reviewer link identity, canonical decision, and durable pending events; `ida_runtime.py` compares and mirrors netnode revisions, then saves the managed IDB. `operator.py` owns local reviewer link/conflict commands. OMP `tool_result` ingests only validated bridge-origin VulFi results into a session-local widget and runs the fixed local CLI after human confirmation; no second MCP client or custom tool for approval.

**Tech Stack:** Python >=3.11, SQLite, IDA Nexus/IDAPython; official MCP client/provider integration from Plan 3; TypeScript OMP extension API (current local `omp` 18.3.2), Bun test runner/lockfile, `pytest`, compiled ELF fixtures.

**Spec:** [Persistence, linking and OMP board](../specs/2026-09-28-vulfi-ida-mcp-design.md) and [operator proposal approval](../specs/2026-09-29-vulfi-re-preparation-design.md).

## Global Constraints

- Netnode v2 remains authoritative for unlinked IDA assessments; SQLite owns external rows and *canonical linked* decisions. No link arises from matching names or address numbers; the operator chooses initial assessment after seeing original-byte/mapping evidence. Link/review operations are local CLI/OMP only, never agent-facing MCP mutations.
- Link verification requires matching original-binary SHA-256, full rule digest, verified address-space mapping to the same call site, live exact finding IDs, and explicit reviewer choice. An IDB-only provisional target cannot link until original binary relationship is verified. Linked pair counts as two findings, not one vulnerability.
- For each linked update: persist pending SQLite event plus external row/decision in one transaction; compare IDB triage/link revision in one worker operation; save IDB; confirm SQLite event only after observed revisions. Expose `pending` during crash window, `conflict` on unexpected revision, `paused` for stale/missing member. No last-write-wins or false atomicity.
- SQLite outage blocks linked edits but permits unlinked IDA triage. A failed IDB save never returns `synchronized`. Replays are idempotent across both crash points and must not duplicate revisions.
- OMP verifies bridge `event.toolName` and trusted `event.details.serverName`/`mcpToolName`, result schema and `isError` before updating. `ctx.ui.setWidget` is only a cached session view; do not change OMP native todo tasks. CLI commands use fixed argv (no shell string) after UI confirmation; shell-capable agents with operator OS credentials remain a documented risk.
- Final release requires actual IDA, Ghidra, radare2, stdio MCP and interactive OMP smoke. Run Python gates with `VULFI_REQUIRE_LIVE=1` and require zero skipped integrations; unsupported provider rule/pass gaps remain visible, with no fake clean result or narrowed provider claim.

## Review Focus

- Two candidates with matching numeric addresses but different image-base/section mapping must not link; test Task 1 with explicit original-byte RVA proof.
- A pending event after IDB save but before SQLite acknowledgment must finalize on restart without incrementing the IDB revision again; test Task 2.
- An offline SQLite catalog must refuse linked triage while allowing unlinked IDA triage, with no silent status drift; test Task 2/Task 3.
- A rescan changes one member's rule digest or occurrence ordinal: pause the link, never attach decision to a similar neighbor; test Task 3.
- An unrelated MCP server returning VulFi-shaped JSON, or an OMP subagent result, cannot alter the main-session board or native todos; test Task 4 and interactive smoke.
