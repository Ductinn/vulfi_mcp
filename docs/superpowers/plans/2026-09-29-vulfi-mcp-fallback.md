# VulFi External MCP Fallback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When IDA lacks a pass or rule's evidence, run vetted real Ghidra/radare2 MCP providers per pass and per rule, persist backend-specific findings, and report unsupported/failed coverage without pretending decompiled text is structured proof.

**Architecture:** Build on [IDA core](2026-09-29-vulfi-ida-core.md) and [preparation](2026-09-29-vulfi-re-preparation.md). `providers/{ghidra,r2}.py` map fixed typed MCP calls into the shared `Candidate`/`PassResult` and `RuleContext` contracts; `providers/client.py` owns trusted connection/schema/binary-identity checks. `prepare.py`/`server.py` select each pass/rule; `catalog.py` owns external scopes and findings. [Plan 4](2026-09-29-vulfi-linked-triage-omp.md) adds human-reviewed cross-store links; do not auto-link by address.

**Tech Stack:** Python >=3.11; official `mcp` Python client (`ClientSession`, `stdio_client`, authenticated loopback transport); pinned candidate Ghidra MCP `bethington/ghidra-mcp v6.0.0` and radare2 MCP `radareorg/radare2-mcp 1.8.8` only after tested tool-schema fingerprints; Java 21/Ghidra 12.1.2 or verified compatible release and radare2 installed in isolated provider environments; `pytest` with live-provider integration markers.

**Spec:** [MCP provider, coverage and persistence design](../specs/2026-09-28-vulfi-ida-mcp-design.md) and [preparation passes](../specs/2026-09-29-vulfi-re-preparation-design.md).

## Global Constraints

- Neither external provider is currently installed/tested locally. Provision actual pinned servers in separate disposable environments during execution; the workstation has Java 25 but the candidate Ghidra MCP documents Java 21/Ghidra 12.1.2. If real tools/schema cannot be verified, report a blocked release gate, not a supported adapter.
- Lock a tested official `mcp` SDK version in `pyproject.toml`/`uv.lock`. Preflight `list_tools` names, input schemas, known response shapes, identity, version and capability fingerprint. Load only fixed Ghidra groups; never expose provider tools, remote tool descriptions, debug/script/raw-command `run_command` or `run_javascript` to the agent.
- Operator config alone specifies executable/args or authenticated loopback endpoint and verified binary-path map. No user-supplied command/URL in MCP calls. Bound pagination, bytes, duration, pass/rule work, and response parsing; release sessions on cancellation. Provider content is untrusted data, never instructions.
- Do not translate pseudocode text into guessed `Param`/CFG facts. Ghidra P-code/dataflow/control-flow and xrefs may justify specific predicates only when response schema and source locations validate. Radare2 1.8.8 appears not to expose safe typed function/type writer tools; mark its auto-apply/review mutations `unavailable` unless real pinned schemas prove otherwise. Do not call raw command tools to work around this gap.
- A decompiler-unavailable IDA result still runs its disassembly-only rules; another backend supplies only rules for which it proves equivalent structured facts. Persist scopes per backend/scan name, and preserve old rows on partial/provider failure. IDB-only input cannot trigger external scan without original binary identity.
- Use per-original-binary SHA-256 SQLite catalog; no SQLite means unavailable, not zero. Run both providers independently on actual fixture binaries before claiming support; one provider passing cannot stand in for the other.
- Keep contributor suites full-suite-safe: live-provider tests may skip with an explicit missing-prerequisite reason by default, while `VULFI_REQUIRE_LIVE=1` makes any missing or skipped required provider a failure. Run each real provider gate under this strict flag; do not treat a skip as passing support.

## Review Focus

- A provider's `list_tools` remains present but changes a required argument/response shape: fail the affected capability instead of translating wrong evidence; test Task 1 and each live adapter.
- A remote path map resolves a same-name, different-hash file: refuse the provider pass and leave prior findings untouched; test Task 1/Task 4.
- `vulfi_prepare` and `vulfi_scan` use separate MCP requests/sessions: re-open or restore analysis so r2 in-memory state loss cannot turn a prepared result into clean zero; test Task 3/Task 4.
- Decompiled C says `strcpy`, but no verified argument/value/call-site facts exist: mark that rule unsupported rather than issue `High`, `Info`, or a negative; test Task 2/Task 4.
- Partial external scan then complete recovery must first retain stale assessed rows, then retire only that backend/scope; test Task 4.

### Task 1: Trusted provider connections, identity, and schema gate

**Files:** Create `src/vulfi_mcp/providers/__init__.py`, `src/vulfi_mcp/providers/client.py`, `src/vulfi_mcp/providers/config.py`, `tests/test_provider_security.py`; modify `src/vulfi_mcp/contracts.py`, `pyproject.toml`, `uv.lock`.

**Interfaces:** Produce `RuleEvidence` in `contracts.py` with JSON-native `backend`, `rule_index`, `contexts` (validated fact dictionaries convertible to Plan 1 `RuleContext`), `ranges`, `state: evaluated|unsupported|failed`, and `reason`. Produce `load_provider_config() -> dict[str, ProviderConfig]` (trusted operator environment/TOML, not MCP args), `def provider_session(config: ProviderConfig, original_path: str) -> AsyncContextManager[ProviderSession]` in `client.py`, and `async def checked_call(session: ProviderSession, tool: str, arguments: dict[str, object], schema_fingerprint: str) -> dict[str, object]`. `ProviderSession` exposes `backend`, `binary_sha256`, `remote_path`, `capability_fingerprint`, `available_tools`; `checked_call` accepts only a backend-specific constant allowlist set by adapters. Remote loopback mapping requires authentication, canonical path and provider-reported/hash-verified identity; if provider cannot attest bytes, read a trusted mapped local file or reject.
